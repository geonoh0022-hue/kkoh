# 수행평가 관리 — 무료 배포 패키지

먼저 **시작하기.html**을 더블클릭하세요. 설치 안내를 브라우저에서 읽을 수 있습니다.

## 구성

- GitHub Free: 소스코드 보관. 학생 자료와 백업 파일은 업로드하지 않습니다.
- Render Static Site: public 폴더를 무료로 게시합니다. Web Service나 Render Postgres를 만들지 않습니다.
- Supabase Free: 로그인 및 자료 저장. 별도의 무료 계정 하나가 필요합니다.
- 오프라인-실행.html: 인터넷과 서비스 계정 없이 실행 가능한 단일 파일입니다.
- schema.sql: 데이터 테이블, 사용자별 접근 권한, 동시 저장 충돌 방지 함수입니다.
- tests/data.test.cjs: 백업 형식 검증 테스트. Node.js 22 이상에서 npm test로 실행합니다.

코드에 외부 라이브러리/CDN 의존성이 없습니다. 화면을 열 때 npm 설치나 빌드가 필요하지 않습니다.

## 무료 사용의 한계

2026-09-23 공식 문서 확인 기준입니다. 무료 정책이나 한도는 변경될 수 있으며 영구 무료 또는 무중단 운영을 보장하지 않습니다.

- Render 무료 Web Service의 로컬 파일은 영구 보관되지 않고 무료 Postgres는 생성 30일 후 만료됩니다. 이 패키지는 둘 다 사용하지 않습니다.
- Supabase Free는 데이터베이스 500MB 한도가 있으며 약 1주간 충분한 사용이 없으면 프로젝트가 일시정지될 수 있습니다. 사용 재개 때 대시보드에서 복구해야 할 수 있습니다. 장기간 방치하지 마세요.
- 전체 자료는 앱에서 4MB 이하로 제한합니다. 브라우저 저장 공간과 무료 환경을 고려한 개인용 크기입니다. JSON 문자 수와 데이터베이스 실제 사용량은 다릅니다.
- 서버는 계정당 전체 자료의 최신 상태 하나를 보관합니다. 서버의 과거 버전 자동 백업은 구현하지 않았습니다. 전체 JSON 백업을 정기적으로 내려받아 별도로 보관해야 합니다.
- 무료 일시정지를 우회하는 자동 호출이나 무료 Render DB 재생성은 포함하지 않습니다.

## 설치 요약

1. Supabase Free 프로젝트를 만들고 SQL Editor에서 schema.sql 전체를 실행합니다.
2. Authentication → Users에서 본인 이메일/비밀번호로 사용자를 직접 추가하고 이메일 확인을 완료/자동 확인 처리합니다. 공개 회원가입은 끕니다. 이 앱에는 가입 화면이 없습니다.
3. 프로젝트 URL과 **publishable key** 또는 기존 **anon key**를 확인합니다. secret/service_role 키를 사용하지 않습니다.
4. GitHub에서 비공개 저장소를 만들고 public 폴더, render.yaml, schema.sql 등 코드를 업로드합니다. public 폴더 구조를 유지합니다.
5. Render에서 New → Static Site → GitHub 저장소 연결. Build Command는 `echo static-files-ready`, Publish Directory는 `public`로 설정합니다. 유료 항목이나 데이터베이스를 추가하지 않습니다. render.yaml을 쓰는 Blueprint 방식도 가능하지만 Static Site 직접 생성이 간단합니다.
6. 발급된 Render 주소에서 앱을 열고 무료 서버 설정을 펼칩니다. Supabase URL/공개 키/이메일/비밀번호를 입력해 로그인합니다.
7. 기존 서버 자료가 없으면 「현재 자료 첫 저장」, 있으면 「서버 자료 불러오기」를 선택합니다. 이후 변경은 약 1.5초 후 서버에 저장됩니다.

다른 기기에서는 동일한 URL/키/계정으로 로그인한 뒤 서버 자료를 불러옵니다. URL과 공개 키만 각 브라우저에 저장하고 로그인 토큰은 메모리에만 보관하므로 새로고침 후 다시 로그인해야 합니다.

## 기존 자료 이전

1. **원래 사용하던 index.html을 원래 브라우저에서** 엽니다.
2. 기존 자료 전체 백업 버튼으로 JSON을 저장합니다. 엑셀은 성적 조회용이며 전체 복원용이 아닙니다.
3. 새 앱에서 전체 백업 가져오기를 선택합니다. 기존 v4 원본 JSON과 v2/v3 자료, 새 백업 형식을 지원합니다. 손상되거나 맞지 않는 형식은 기존 내용을 바꾸기 전에 거부합니다.
4. 서버가 비어 있을 때 첫 저장을 누르고 **서버 저장 완료**를 확인합니다.
5. 새 브라우저/다른 기기에서 로그인해 서버 자료를 불러오고 학교, 학생, 점수를 확인합니다. 그 후에도 기존 백업은 보관하세요.

## 일상 사용과 충돌 처리

- 먼저 로그인 → 서버 자료 불러오기 → 작업 → 서버 저장 완료 확인 순으로 사용하세요.
- 인터넷 장애 시 브라우저에 저장됩니다. 자동 저장 실패가 표시되면 전체 백업을 받고 연결 복구 후 저장 재시도를 누르세요.
- 서버에 없는 변경을 남긴 채 새로고침했다면 먼저 로컬 자료를 전체 백업하세요. 서버 자료를 불러온 다음 백업을 가져와야 서버에 반영할 수 있습니다. 가져오기는 병합이 아니라 전체 교체입니다.
- 다른 기기에서 먼저 저장하면 자동 덮어쓰기를 차단합니다. 이 기기의 백업을 받고 서버 자료를 불러와 비교하세요. 필요한 변경은 다시 입력하거나, 의도적으로 백업을 가져와 전체 교체하세요. 자동 병합은 하지 않습니다.
- 같은 브라우저의 여러 탭에서 편집하면 기존 탭의 편집을 막습니다. 백업 후 하나의 탭만 다시 열어 사용하세요.
- 로그아웃은 현재 자료를 백업 다운로드한 뒤 브라우저의 작업 내용을 비웁니다. 서버의 자료는 유지됩니다. 미저장 루브릭 초안은 루브릭 저장 버튼으로 먼저 확정하세요.
- 로컬 작업 자료와 JSON 백업은 평문입니다. 개인 기기에서 사용하고 백업 파일은 안전한 개인 저장소에 보관하세요.

## 장기 보관과 서비스 이전

매주 및 학기 마감 때 전체 백업을 내려받아 컴퓨터와 별도 저장장치 두 곳에 보관하세요. 파일이 실제 다운로드되었는지 확인하고, 정기적으로 오프라인 실행본의 별도 브라우저에서 복원을 시험하세요. 브라우저가 여러 파일 다운로드를 막으면 다운로드 허용 후 전체 백업을 직접 누르세요.

서비스가 중단되면 오프라인-실행.html을 열어 마지막 전체 백업을 가져옵니다. 백업 이후의 변경은 복구할 수 없으므로 서버 저장만 믿고 백업을 생략하지 마세요.

새 Supabase 프로젝트로 이전할 때는 schema.sql을 실행하고 새 사용자를 만든 뒤 새 URL/키로 로그인해 JSON을 가져오고 첫 저장을 합니다. 사용자 UUID가 바뀌어도 JSON 가져오기가 가능합니다. 화면은 public 폴더를 다른 정적 호스팅으로 옮길 수 있습니다. 다른 데이터베이스로 직접 이전하려면 cloud.js의 통신 부분을 수정해야 합니다.

비밀번호 분실 시 프로젝트 소유자가 Supabase Authentication의 사용자 관리 또는 공식 복구 절차를 사용하세요. 사용자 계정을 삭제하면 그 사용자 서버 자료도 삭제되므로 계정 재생성 전에 반드시 백업하세요.

## 검증 범위

- 백업 검증 단위 테스트 4개 통과.
- Edge 브라우저 자동화: 학생/평가/루브릭/채점, 첫 서버 저장, 자동 저장, 통신 장애 재시도, 응답 유실 재시도, 충돌 차단, 전체 백업/복원, 잘못된 백업 거부, 서버 불러오기, 로그아웃 확인.
- 인터넷 차단 상태에서 단일 HTML 실행 및 학교 등록 확인.
- 데스크톱/모바일 화면 확인.
- 실제 Supabase 계정, SQL 실행, RLS 권한, GitHub/Render 배포는 아직 수행하지 않았습니다. 실제 사용 전 아래 검증을 완료하세요.

### 실제 배포 후 확인

가상 학생 한 명으로 저장 → 다른 브라우저에서 불러오기 → 백업 후 복원 → 두 기기에서 같은 자료 편집 시 충돌 차단을 확인합니다. Supabase에서 테스트용 두 번째 사용자를 만들어 로그인했을 때 첫 번째 사용자의 서버 자료가 나오지 않아야 합니다. 로그아웃 상태의 API 요청도 자료를 읽지 못해야 합니다. 이후 실제 자료를 가져오세요.

### 개발자용

`public/index.html`은 기존 앱, `public/data.js`는 백업 검증, `public/cloud.js`는 인증·REST 통신·백업 UI를 담당합니다. 서버 저장은 RLS와 SECURITY INVOKER 함수로 사용자별로 격리하며 UUID revision 비교로 충돌을 감지합니다. 네트워크 응답이 유실되면 동일 UUID의 요청을 재시도합니다. 로컬 수정 중에는 서버 데이터를 자동으로 불러오지 않습니다.

오프라인 실행본을 업데이트하려면 `node make-offline.cjs`를 실행합니다. npm test는 추가 패키지 없이 실행됩니다. 브라우저 테스트는 `npm install --no-save playwright`와 `npx playwright install chromium` 후 `node tests/browser.cjs`로 실행할 수 있습니다. Windows Edge가 설치되어 있으면 `BROWSER_CHANNEL=msedge` 환경변수를 사용할 수 있습니다. 테스트는 로컬 서버와 모의 API를 사용하며 실제 계정으로 전송하지 않습니다.
